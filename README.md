# Монітор розрахунків

Робоче місце комплаєнс-аналітика: звірка розрахунків за договорами на відкритих
даних [spending.gov.ua](https://spending.gov.ua). Кожен платіж Казначейства
привʼязується до договору за номером і датою з призначення платежу і звіряється з
ціною договору, актами й додатковими угодами; розбіжності й ознаки порушень
закупівельних правил стають сигналами ризику.

- Сайт: GitHub Pages, встановлюється як додаток на телефон і компʼютер (PWA).
- Дані: GitHub Actions оновлює `data/` кожні 6 годин — spending.gov.ua і Prozorro.
- Вхід: Google (Firebase Authentication), будь-який обліковий запис Google.
- База: Firestore (проєкт `spending-monitor-2122b`) — статуси перевірок і документи
  організацій; правила доступу — `firestore.rules`.
- Google Диск: досьє й реєстри зберігаються у власний Диск користувача.
- Мова інтерфейсу: українська або англійська.

## Версії

Номер — у `VERSION`, зміни — у [CHANGELOG.md](CHANGELOG.md). До 1.0.0 триває
розробка; 1.0.0 буде першою промисловою версією. Під час публікації
`tools/stamp.py` вписує у сайт версію і збірку (версія + хеш коду), тож браузер
завжди бере свіжі файли, а service worker (`sw.js`) пропонує «Оновити», щойно
вийшла нова збірка. Оновлення лише даних збірку не змінює.

Папка `pages/` — git-копія репозиторію; вхід у GitHub — через GitHub CLI
(`gh auth login`, ключ лежить у звʼязці ключів macOS). Публікація коду:

```bash
git pull --rebase && git commit -am "що змінилось" && git push
```

GitHub Actions часто комітить оновлення `data/`, тому перед `push` завжди
`git pull --rebase`. Кожен push запускає синхронізацію й публікацію сайту.

Правила бази (`firestore.rules`) публікує Firebase CLI (`firebase.json`,
`.firebaserc` — проєкт `spending-monitor-2122b`):

```bash
firebase deploy --only firestore:rules
```

Без git можна й так: `python3 tools/publish.py -m "..."` з токеном у
`~/.config/spendings/github-token`.

## Як додати або прибрати організацію

Додати: у додатку на сторінці «Організації» впишіть код ЄДРПОУ й натисніть
«Додати». Заявка потрапляє в Firestore (`watchlist`), а GitHub Actions кожні
10 хвилин перевіряє нові заявки й запускає синхронізацію. За 10–20 хвилин
організація зʼявиться в списку, а її документи — у базі.

Прибрати (або додати без додатка): **Actions** → «Синхронізація і публікація» →
**Run workflow**, код ЄДРПОУ в полі «Прибрати організацію» (або «Додати»).

## Як це влаштовано

- `sync/sync.py` опитує портал і оновлює файли в `data/`.
- `sync/tracked.py` — договори на контролі: список у Firestore (`tracked`),
  знімок кожного договору з історією змін і платежами — у `data/tracked/`.
- `tools/drive-sync.gs` — Google Apps Script, що копіює документи договорів на
  контролі на Google Диск користувача (Prozorro не дає завантажувати файли зі
  сторінки) і веде таблицю-реєстр.
- `sync/prozorro.py` забирає з Prozorro процедури організації (етапи оплати,
  договори, зміни, документи) у `data/org/<ЄДРПОУ>/prozorro-<рік>.json` і
  звіряє договори Prozorro з договорами Казначейства. Пошук на prozorro.gov.ua
  дозволяє 60 запитів на хвилину, тому перше завантаження триває 20–30 хвилин;
  `SKIP_PROZORRO=1` пропускає цей крок.
- `sync/analysis.py` звіряє договори з актами й платежами і рахує сигнали
  (`data/org/<ЄДРПОУ>/analysis.json`, `data/signals.json`). Сигнали зберігаються
  як числа, текст формулює сайт мовою читача.
- `index.html`, `app.js`, `style.css`, `i18n.js` — сам сайт; `cloud.js` — вхід,
  Firestore і Google Диск; `sw.js` і `manifest.webmanifest` — встановлення й кеш.
- `tools/icons.html` малює PNG-іконки з `icon.svg` (логотип UP&D).

Файли в `data/`, крім `orgs.json`, створюються автоматично.

## Запуск на своєму компʼютері

```bash
python3 sync/sync.py            # оновити дані
python3 -m http.server 8020     # відкрити http://localhost:8020
```
